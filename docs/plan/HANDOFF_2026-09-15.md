## 3. What was built

### Three skills, in `.claude/skills/`

| Skill | Job |
|---|---|
| `susie-triage` | Cluster many failures into a short ranked list of root causes. Reads suite results **and** the live obs store. |
| `susie-debug` | One bug, report to proven fix. `SKILL.md` + 5 references derived from code and git history. |
| `verify-call` | "Does Susie still work?" as a number against the 97% bar. |

`susie-triage --obs` is the one to know. It reads the production `calls` table,
excludes operator test calls by `caller_number`, and computes two derived
signals nothing else reports:

- **`PHANTOM_BOOKING`** — `booking_confirmed` set, no provider id. Such a call
  stores `success=true`, `outcome=booked`, `quality_score=5` — every existing
  signal calls it perfect.
- **`DORMANT_SCREENING`** — a red-flag screen armed and never fired.

### `docs/INCIDENT.md`

Restore → communicate → diagnose. Severity 1 is *a booking the caller believes
exists but does not*. **Nine `FILL:` blanks remain** — on-call number, Render
service names, clinic contacts. Only Quentin has them.

### `booking_not_written` alert (`app/obs/alerts.py`)

Critical/immediate SMS when Susie confirms a booking and no calendar id comes
back. Gated on `calendar_backed(clinic_id)`, which resolves through
`clinic_config.get_clinic()`. Runs in `_cleanup()`, post-call — no live-path
latency. Still behind `OBS_ALERTS_ENABLED`.

### Test-infrastructure repairs

- **60 mined regression scenarios were unreachable.** `run_tests.py` built its
  list from `ALL_SCENARIOS` (118) and never included them. Added
  `--regressions`, `REGRESSION_SCENARIOS`, `SELECTABLE_SCENARIOS`.
- **They then ran against the wrong clinic.** Nothing carried a target, so a
  Theorem recording was driven through Northgate's config and passed vacuously.
  Added `tests/auto/scenarios/replay_targets.py` — a producing clinic maps to a
  number that is safe *and* same-lineage, or the scenario refuses to run.
- **`jv_v1_test`** — replay-only copy of JV's config on `+447700900001` (Ofcom
  drama-reserved, never routable), with its own throwaway calendar. 60/60
  runnable.
- **`persona_sweep.py`** — drives all 16 harness personas, ~£0.05 a run.

## 4. What was found — including three things I got wrong

Read this section carefully. Three of my own confident findings were wrong, and
the way each was caught is the reusable part.

### Real and confirmed

1. **`booking_confirmed` does not mean a booking exists.** It is set in
   `flow.py` where the confirmation *sentence* is composed, not where the write
   succeeds (four sites). `tests/auto/evaluator.py` calls that field "the
   authoritative source". So the field, the judge and the suite can all agree a
   call was perfect while nothing was written. **Zero instances in 449 calls** —
   but the structural gap is real and `booking_not_written` now guards it.

2. **`final_state` is unusable.** All 929 stored calls report `GREETING`,
   including the 46 completed bookings. Never advances past its initial value.
   It is the natural first field to reach for and it will mislead.

3. **`lat_baseline` silently dropped 7 of 16 latency fields.** Wire names vs
   stored keys (`cache_read` ← `cache_read_tokens`, and six more). Stored-call
   latency analysis carried no prompt-cache counters, token counts or
   inter-token timing while raw log lines had them all. Fixed in `9efc1c39`.

4. **Two tests had been red for ~19 days** on expired hardcoded dates. One of
   them (`test_scarcity_*`) was worse than red: its expired day was filtered
   out, so *"multiple days are still refused"* was asserting against a single
   day and the refusal stopped being tested while still looking tested.

5. **`app/obs/regress.py` cannot detect a code regression.** It imports no `app`
   code and asserts only against each scenario's frozen `transcript`. Verified
   empirically. It is a lint over recorded text, not a regression runner.

6. **Gate 5b reasoning leak** — *"Wait, actually — don't cancel it…"* reached the
   caller. `known-bugs.md` class 9 has this fixed before. Small, real, open.

### Wrong, and how it was caught

1. **"The Carepatron clinics store no booking id."** I read `booking.system`
   from `clinic.json` — the line clinics give *patients*. The runtime
   integration is `booking_system`, and jv_v1/northgate write to
   **google_calendar**. Caught by querying the live store and seeing 103 calls
   with a `calendar_event_id`. *Lesson: the config field a human reads and the
   one the code uses are different fields.*

2. **My own alert was silently off on the live clinic.** Theorem reports as
   `theorem_v3`, built in `clinic_config.py` with no `app/clinics/` directory;
   my helper looked for a `clinic.json`. Caught by the same store query. *Lesson:
   test against the id the runtime actually emits, not the one in the tree.*

3. **"A live repeat loop on 9 of 16 personas."** I localised it precisely, found
   two prior fixes in git, and was one edit away from changing `connection.py`.
   Every persona carries a phone number different from the driver's caller ID;
   Susie correctly offers the keypad; `driver.py` says the DTMF path is
   *"deliberately NOT modelled"*. Caught by one controlled experiment:

   | `book_bare` | turns | booked | findings |
   |---|---|---|---|
   | phone differs from caller ID | 14 | False | 2 |
   | phone matches caller ID | 9 | **True** | **0** |

   *Lesson, and the one worth keeping: a finding from a harness is a claim about
   the harness until you change the single variable and re-run.*

## 6. How to work in this repo

The traps that cost me time, in `susie-debug/references/gotchas.md`:

- **Measure against `origin/*` after `git fetch --all`.** Local refs go stale;
  this checkout was 13 commits behind its own remote.
- **Engine work lands on `origin/latency-eval`.** ADR-002 names
  `engine/converged` canonical; that branch exists only in local clones and has
  not moved since 2026-08-06.
- **Commit dates here are unreliable.** Order by topology
  (`git merge-base --is-ancestor`), not date.
- **`flow.py` is frozen.** `handle_transcript()` is one 16,010-line method.
  Smallest possible diff, one reproduced defect, one regression test.
- **`receptionist_tools.py` has 127 broad `except` clauses of 163.** That is the
  machinery behind the worst failure mode this system has.
- **Clinic behaviour belongs in `clinic.json`.** If a fix would have to be
  repeated on another branch, it is in the wrong place — that is what made name
  capture get fixed ten times in 25 days.

### Commands worth knowing

```bash
# what is wrong with the live clinics right now  (needs OBS_DATABASE_URL)
python .claude/skills/susie-triage/scripts/collect_failures.py --obs --days 30

# what breaks when 16 different callers ring        (~£0.05, ~10 min)
HARNESS_LIVE_LLM=1 python scripts/persona_sweep.py --clinic jv_v1

# the free-form booking-flow invariants, all clinics
HARNESS_LIVE_LLM=1 pytest tests/harness/test_this_branchs_booking_flow.py -q

# re-drive a mined real call against current code
python tests/auto/run_tests.py --scenario regression_<id>
```

does **not** need `OBS_CAPTURE_ENABLED` — that flag gates writes.
