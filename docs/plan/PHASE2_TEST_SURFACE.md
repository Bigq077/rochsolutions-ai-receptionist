# Phase 2's test surface, measured

Prep for `SLOT_PRESENTATION_CONVERGENCE.md` Phase 2 — one producer, one record.
Written 2026-09-03. **The plan's stated test risk was wrong, and it was wrong in
the safe direction: the surface is far smaller than it said.**

---

## What the plan said

> ⚠️ `tests/auto/scenarios/regressions/` pins presentation text in ~30 files.
> **Read them, never bulk-edit — some pin a DEFECT's wording.**

That was the second of Phase 2's two named risks, and it is the one that made
the refactor look like a full day's work rather than a session's.

## What is actually there

### `tests/auto/scenarios/regressions/` pins NOTHING. 61 files, checked.

Every one is auto-generated by `app/obs/to_scenario.py` from a real judged-bad
call. Presentation text appears in the `transcript` field — which is a
**historical record handed to the evaluator as context**, not an assertion.

The assertion is `expected`, and across all 60 scenarios it is:

```
expected = {'no_technical_error': True}      60 of 60
```

**Zero of them assert any wording.** Parsed with `ast.literal_eval`, not
grepped, and no `expected` value anywhere is prose. Changing the sentence
cannot break them.

They also do not run in the ordinary suite: `tests/auto` makes **real outbound
calls** and is gated behind `RUN_LIVE_CALL_TESTS=1` plus
`CALL_TEST_TARGET_ALLOWLIST`. That guard exists because this suite once booked
60 real appointments. They are the 20 `skipped` in every run.

### The real surface is 30 files in `tests/regression/`, and 28 are harmless

Those 30 contain a presentation literal. Classified by whether the literal
appears in an ASSERTION or only as fixture input:

| | count | meaning |
|---|---|---|
| fixture input only | **28** | the wording is an argument, not a claim. Free to change |
| asserted | **2** | read before touching the opener |

The 28 build a sentence to feed a parser, a guard or a record. Any sentence of
the right shape would do; none says the words must be these words.

### The two that assert, in full

**1. `test_the_offer_and_its_record_are_built_together.py:91`** — the only
positive literal pin in the codebase:

```python
assert offer.chunks[0].startswith("Here's what we've got coming up — Number 1,")
```

If Phase 2 changes the multi_day opener, this is **one line**. It is pinning
that an opener exists and leads the first chunk, so re-aim it at whatever the
single producer emits; do not delete it.

**2. `test_p9_more_times_that_day_is_numbered_and_recorded.py:184,219,220`** —
NEGATIVE, and it carries a decision:

```python
assert "The available slots for" not in spoken
```

A CONTINUATION must not use the plain completeness opener. That is P10, and
`build_slot_offer`'s own docstring states it: *"A continuation must never use
the plain one."* Keep this assertion through Phase 2 whatever the wording
becomes — the string changes, the rule does not.

## What this does to Phase 2

The plan's two named risks were the ~30 pinned files and the deletion itself.
**The first is one line and one preserved contract.** What remains:

* deleting `_flush_slot_buf` sections 3a–6 and ~340 lines of reverse-parsers,
  keeping sections 1, 2, 7, 8 and `reconcile_readback_time`;
* the `Offer` record replacing the ten session keys.

Both are now covered by verification that did not exist when the plan was
written:

* **`scripts/sweep_slot_offer.py`** — 528 generated diaries, seven invariants,
  proven to fail. Run it after every deletion step.
* **`scripts/replay_day_picks.py`** — the language half, over 828 real calls.
* **`calls.slot_offers`** — accumulating real payload/offer pairs from
  2026-09-03, so within a week the deletion can be diffed against what
  production actually said.

## The method note worth keeping

**The plan named the wrong directory.** `tests/auto/scenarios/regressions/`
and `tests/regression/` are both "regression tests" by name, and the risk was
attributed to the one with 61 files rather than the one with the assertions.
Nobody had opened either.

That is the third thing in this document to have been carried forward as true
without a grep — F1 and F2 were the other two, and both were already built.
The pattern is not carelessness, it is that a plan written from defect docs
inherits their claims. **Grep before writing the task, not before doing it.**
