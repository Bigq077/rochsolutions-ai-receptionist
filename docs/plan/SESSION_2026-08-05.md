## 2. The three defects

### `B-57` — Theorem could not cancel · **the significant one**

**The gate armed on a literal, and the prompt mandated a different one.**
`_cancel_retention_asked` required `"altogether"`, from the retention question
*"…or cancel it altogether?"*. Theorem's prompt mandates the other sanctioned
wording — *"shall I go ahead and cancel that?"* — which contains no `"altogether"`
at all. So every time the model obeyed its own instructions, `cancel_appointment`
was refused.

**This is a shape, not an incident.** It is the third instance:
`_booking_confirmation_asked` (R6) and `_move_confirmation_asked` were the first
two. A single-literal write gate meeting a prompt that mandates different wording
will fail silently and look like a model problem.

Two halves fixed:

- **Arming.** A new `_direct_cancel_cta` recognises single-action cancel asks.
  It requires **both** an ask shape and a cancel verb, so a statement cannot arm
  the gate — and the booking and reschedule re-steers, which carry an ask shape
  but no cancel verb, still cannot. That leak is asserted shut.
- **Consent.** `_cancel_reply_consents` now takes the session and accepts a clear
  affirmative **only** when the ask named one action. Against the retention
  question an explicit `"cancel"` token is still required, because a bare "yes"
  answers an OR and identifies nothing.

**Deliberately conservative, because this deletes things.** The affirmative is
judged by `_book_verdict_deterministic`, which settles negation and correction
*before* the yes and returns `'unsure'` — which blocks — rather than guessing. No
classifier decides a deletion. Every negation, reschedule word and "keep/leave it"
still blocks ahead of all of it.

One detail worth keeping: consent reads through `_cta_asked` rather than
`last_bot_prompt` directly, so the **uncapped** `last_question` is consulted. A
cancel read-back naming service, practitioner and site runs past the 200-char cap
(`B-38`), and the truncated form would have silently fallen back to demanding the
token — a bug that would only appear on the *longest* read-backs.

### `B-39` — the retention question · **also Quentin's bonus item**

The cause was one clause. Both prompt engines said the question was *"REQUIRED on
the cancel path **EVERY TIME**"*. That is true of the **call** and false of the
**turn** — and "every time" is precisely the reading that loops. Evidence: asked
three times in 27 seconds on one call, and on `CAe74ceae7` re-emitted **in the
same turn as the cancellation**, so the caller heard the question and then
immediately heard it being done.

Replaced with a **count** — *ASK IT ONCE PER CALL* — plus the answer shapes that
discharge it and three named prohibitions. Each of the three sightings maps to one
prohibition.

**Quentin's ask was to take the question out of the reschedule flow**, and that is
now an explicit prohibition in both engines: never ask a caller who is *moving* an
appointment whether they would rather cancel it. They are trying to keep it, and
the question invites them to lose it.

> ⚠️ **The `"altogether"` wording deliberately stays in the cancel turn.** Until
> `B-57` it was load-bearing — the gate armed on that literal and nothing else.
> `B-57` removed the coupling, but retention is wanted, so the phrase stays. The
> two fixes shipped together so neither stands on the other.

### `B-40` — the stalls · **mitigated, not closed**

`_FILLER_TOOLS` mapped `check_availability`, `book_appointment` and
`lookup_patient` — and **not** `cancel_appointment` or `reschedule_appointment`.
The two turns where a caller is most anxious, both of which make a calendar
round-trip *after* the caller's go-ahead, were the two with no filler pool at all.
11.1 s of silence measured on a cancel.

Both are now mapped to new `CANCEL_WRITE_FILLERS` / `RESCHEDULE_WRITE_FILLERS`.
A gate refusal returns *before* the filler branch, so a filler can never be spoken
over a write the gate just refused.

**Quentin's second ask, done in the same change:** "bear with me" and "just a
second" are gone from every pool that can play on these turns —
`LOOKUP_FILLERS`, `THINKING_FILLERS_SECONDARY`, `config.FILLER_PHRASES` — replaced
with warmer wording that does not lengthen the turn.

> 🔴 **Read this as mitigated.** The underlying cause is the chunk gate holding
> output for ~10 s and it is **untouched**; and the filler *path* still only arms
> when a tool is detected early, which is exactly what failed in the original
> sighting. **A cancel turn can still go quiet.** Watch `ttfa_ms` on sweep cases
> A3 and B3.

### One finding that came out of the fix

Two of my replacement filler phrases were caught by the new test for making a
**false completion claim**: *"Getting that all booked in for you…"* trips
`_false_write_claim`. That is the `B-36` shape appearing in **filler text** rather
than in a model utterance — a place nobody had looked. Worth knowing it is
possible.

## 3. `B-55` — a scope pin that expired at midnight

Not a call defect; a **test-integrity** defect, and it had to be fixed first
because everything else depended on it.

`test_b55_provisional_reschedule_closing.py` pinned prompt hashes to prove a
change was scoped to one clinic. But the rendered prompt interpolates today's
date, so the hashes changed **every midnight** — the pin failed daily regardless
of whether any wording had moved, which makes it worthless exactly when you need
it: while judging whether *your own* change leaked into another clinic.

Fixed by hashing a **date-normalised** render — weekday names, month names and
digit runs redacted — so the hash moves only when the *wording* moves.

> Note the direction: `theorem-onboarding` **already had** this fix. The better
> test was on the clinic branch and the canonical branch lacked it, which is the
> same canonical-first inversion the Vital Edge plan was written to repair.

With that in place the scope guarantee is real, and it held on both branches:
only `jv_v1` and `theorem_v3` moved, both intended; `demo` and `theorem`
byte-identical.

### 🔴 It was worse than one dead test — it was three

Measured while verifying the baseline, and this is the finding worth carrying
forward. **Two other regression files import that same hash table and `_sha`:**

```
tests/regression/test_b55_provisional_reschedule_closing.py   ← owns the table
tests/regression/test_reason_question_once.py                 ← imports it
tests/regression/test_under_age_booking_gate.py               ← imports it
```

So the expired pin was not failing one scope guarantee, it was failing **three**,
every day, on three separate clinic-containment claims — including
`test_under_age_booking_gate.py`, which exists to prove an under-18 refusal did
not leak into another clinic's prompt.

**Why that is dangerous rather than merely untidy:** all three fail *permanently*
and for a reason that has nothing to do with the thing under test. A guarantee
that is always red is indistinguishable from a guarantee that has been broken,
and the only rational response to a permanently-red test is to stop reading it.
That is precisely the state three containment claims were in.

**Six tests went green as a result** — the four `b55` hash cases plus one each in
the two importing files. All six trace to this single cause; none is a behavioural
change.

> **Lesson for future pins: a shared hash table is a shared single point of
> failure.** Convenient, and correct here — one table, one truth — but it means a
> defect in the helper silently disables every test that imports it.

### A method note on the baseline — three ways of measuring it failed first

Recorded because this cost real time and will cost it again otherwise.

- **`git stash` does not revert in this tree** (OneDrive file locks). Known, in
  `CLAUDE.md`.
- **`git worktree` is unavailable** — the sandbox blocks *all* `.git` writes, so
  `worktree add` fails on `commondir` regardless of where the worktree is placed,
  inside the workspace or out. **New; not in `CLAUDE.md`.**
- **A failed baseline capture is silent.** The first attempt diffed against a
  baseline file that had never been written, so all 93 failures looked "new". A
  diff against an empty file looks exactly like a catastrophic regression.
- **zsh does not word-split unquoted variables**, so `for f in $FILES` iterated
  once over the whole string and reverted nothing — while reporting success.
  Caught only because `git status` was checked immediately after.

What worked, and is the method to reuse: revert by explicit pathspec with
`git show <sha>:<path> > <path>`, move untracked new tests aside, run, then restore
— and **verify the restore**. On `theorem-onboarding`, where uncommitted work was
at risk, that meant md5-ing all nine files before and after and confirming
byte-identity. On `latency-eval` everything was already committed, so
`git checkout HEAD -- <path>` was sufficient and exact.
